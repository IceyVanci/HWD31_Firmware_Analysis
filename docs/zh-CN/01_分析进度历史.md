# HWD31 逆向研究 — 分方面探索进度与结果

> 本文按“探索方面”组织，而不是按时间顺序记录。
> 对象：HWD31（au Speed Wi-Fi NEXT W01 / KD02 / MIZUHO）的 SIM 网络锁。
> 覆盖 2026-10-15 → 2026-10-21 的主要工作；原始证据、固件镜像、脚本与样本不随本仓库发布。
> 结论先行：锁机制已完整解析；在“不拆机、不用官方渠道、只靠运行中的系统”约束下，软件层未找到可用解锁路径；非软件路径均需拆机、焊接或官方/第三方渠道。

---

## 1. 目标、约束与核心难点

**目标**：离线推导 8 位 SIM 解锁码，并且只提交一次；错误 10 次将永久锁死。

**约束**：
- 不拆机、不焊接、不使用官方/付费解锁渠道；
- 不盲试 `^CARDLOCK`，不触碰 `^SPWORD`；
- 优先只读探测；写操作必须可回滚。

**核心难点**：
- 解锁码是产线写入的哈希原像，不是 IMEI 的函数；
- 校验所需的 hash+salt 只存在于调制解调器 NV 0xC546（50502 / E0）与 0xC547（50503 / E1）；
- 因此理论路径只有一条：读出 NV 记录 → 离线暴破 → 单次提交。

## 3. 方面 A：SIM Lock 机制与验证链

### 3.1 验证链

```text
code(8 位数字)
  → SHA256 → h1(32B)
  → SHA256(h1 ‖ salt(32B)) → h2(32B)
  → h2 == NV 0xC546[0:32] ?
成功 → 解锁标志 *(GP+0x18fd)=0
失败 → 全局计数 +1（上限 10，NV 50005）
```

- 记录长度 0x19B（411 B）；salt 位于记录 `0x40:0x60`；
- 验证器 `0x020623e8` 要求 8 位纯数字；核心比较在 `0x02062678`；
- 槽位：`"OEM" → 0xC546`（50502 / E0），`"SIMLOCK" → 0xC547`（50503 / E1）；
- `^DATALOCK` 是 E0 的提交口：参数 `{码,1,IMEI}`；失败返回 `+CME ERROR:16`；本地 RAM 计数 3 次/启动，**不消耗 `^CARDLOCK` 次数**；
- `^CARDLOCK` 的 SET 在本镜像被恒拒（`+CME ERROR: 3`），只能查询；
- 关键否定：设备端不存在 `code=f(IMEI)` 算法；`^NVRDEX` 在本机固件不存在；外部工具依赖的 NV 读路径失效。

### 3.2 计数与提交纪律

- 锁状态长期为 `^CARDLOCK: 1,10,0`（10 次机会，**0/10 消耗**）；
- `^MAXLCKTMS=10`；`^SPWORD` 是独立 3 次限制，风险高于收益，全程未触碰；
- 从未提交过任何解锁码；`^DATALOCK` 只用于历史候选码的免计次验证，全部返回 CME16。

**本方面结论**：机制已完整解析；唯一可行路径是读取 NV 0xC546 的 140 B 记录（hash+salt），离线暴破后单次提交。

## 4. 方面 B：锁命令、写入门控与提交面

### 4.1 AT 命令面

- `dsat_huawei_sim`：`^CARDLOCK`（查询 + SET 恒拒）、`^AUTHVER`、`^SPWORD`、`^GLASTERR`、`^RDCUST` 等；
- `dsat_huawei_ext`：`^DATALOCK`、`^SETHWLOCK`/`^TESTHWLOCK`、`^SIMLOCK`、`^RSFR`/`^RSFW`、`^SSID`/`^WIKEY`/`^WUPWD`/`^SKU` 等；
- `dsat_huawei_dload`：`^DLOADVER`/`^DLOADINFO`/`^NVBACKUP`/`^NVRESTORE`/`^NVRSTSTTS`/`^AUTHVERIFY`/`^GODLOAD`/`^SUPINFO`/`^SN` 等。

### 4.2 写入门控

| 通道 | 门控 | 锁定设备可用性 |
|---|---|---|
| `AT^DATALOCK="码"` | 无状态门控；3 次/启动 | ✅ 可提交，不耗 CARDLOCK（预言机） |
| `AT^CARDLOCK="码"` | 设计恒拒 | ❌ |
| `^SETHWLOCK`/`^TESTHWLOCK` | 需未锁状态 | ❌ |
| `^RSFW`（写 EFS） | 需先解 datalock；仅 SIMLOCK 可写 | ❌ |
| FTM 写（`^SSID` 等） | 需未锁 | ❌ |
| `^RSFR`（读） | 静态无门控 | ✅ |

### 4.3 结论

- 锁定设备没有可直接写 NV 或绕过 10 次计数的锁命令；
- `^DATALOCK` 是唯一低成本的试码口，但它只写 RAM 状态，不解锁；
- `^CARDLOCK` 绝不能盲试；任何候选码必须先经 `^DATALOCK` 或其他只读手段验证。

## 5. 方面 C：设备通道与控制面

### 5.1 USB 模式与枚举

- 初始 `12d1:1F01`（CD-ROM）；SCSI CDB `11 06 00 00 00 00` → `12d1:1442`（服务模式：COM13=AT / COM14=应用口）；
- 通过 CDB、厂商控制请求 `C0 9A`、app_pcui 三条 PC→设备切换通道，可达 1441、1566、1001、155E、157E 等组合；
- 组合脚本执行器只有 3 个：工厂 shell、开机 `start_usb`（固定 1F01）、`mbimd`（唯一自动执行者）；
- 结论：USB 模式切换本身可控，但不能凭空创造 diag 通道。

### 5.2 AT 通道

- 服务模式 COM13/COM14；后期以 COM26 @115200 直连 AT；
- 只读探测：`^RSFR`、`^NVRDEX`、`^MAXLCKTMS`、`^DATALOCK?`、`^CARDLOCK?`、`^SFEATURE?`；
- `^RSFR` 可读 SIMLOCK 与 14 类 LOGSAVE 日志，但不含 hash；
- `^NVRDEX` 双测均 ERROR，确认固件无此命令。

### 5.3 WebUI / WiFi

- 设备 WiFi 热点与 WebUI 可完整控制，且与 USB 模式解耦；
- 登录使用 `password_type=4` 的挑战哈希；表单接口 `csrf_token` 需 `csrf:` 前缀，AJAX 用请求头；
- 可用接口：`/api/device/mode`、`/api/device/control`、`/api/pin/simlock`、`/nvram.bak` 下载、`/api/nvramul.cgi` 恢复、`/api/filemanager/upload`、`/api/dialup/*` 等；
- 结果码：`125003`=无权限/路径被拒；`100001`=参数或内容错误；`100005`=参数校验失败。

### 5.4 adb

- MI_04 标记为标准 ADB 接口；`adbd` 未运行（init 卡在 `f_mtp`，`persist.service.adb.enable` 未设）；
- 静态证据显示 adbd 为 root/userdebug，一旦启动即 root shell；
- WinUSB 直连 OUT 超时，手搓 CNXN 无响应；未取得 shell。

### 5.5 diag / QCDM

- 普通组合不执行组合脚本；`echo diag > f_diag/clients` 只存在于组合脚本；
- 1442/1441/1001/155E 等已测试的可达组合中，diag 对 PC 全部沉默；ROM 中另有 157E（含 diag+pcui）组合，但无脚本触发。
- 结论：`f_diag` 数据链路未注册/未启用，diag 是“僵尸接口”；需要 mbimd 或组合脚本才能复活，而 PC 不可触发。

### 5.6 结论

- 已获得稳定的 WebUI/WiFi + AT 控制面；
- 没有 diag、adb、root shell；
- 通道本身不是瓶颈，瓶颈是“通道能触达什么”。

## 6. 方面 D：固件解包与静态逆向

### 6.1 镜像与工具

- 官方升级 ZIP、解包脚本、modem 镜像、boot 镜像、rootfs/app/WebUI/ramdisk 提取树；
- modem 重建为 `modem_full.elf`（约 48 MB）；内核重建为 `boot5_vmlinux.elf`（68,908 个 kallsyms 符号）；
- 工具：Ghidra 12.1.4、JDK 21、REA 与自定义脚本；AI 辅助整理。

### 6.2 modem

- 指令集为 Hexagon（QDSP6）；段 #17 为日志描述符数据库（2.66 MB，166,355×16B，1,486 模块）；
- NV 服务位于 `0x0205DFxx–0x0205E5xx`；item 映射 16 项：`0x22 → 0xC546`、`0x2A → 0xC4F2`、`0x2B → 0xC542` 等；
- SMEM 0x86 magic：读 `0x2014AA55`、写 `0x2014A5A5`、成功 `0x201455AA`；
- 12 个 dload/工具类命令处理器；`^CARDLOCK` 查询与 SET 链；`^RSFR`/`^RSFW` 处理器。

### 6.3 内核与 `/dev/nv`

- `/dev/nv` 协议：12 B 头 + 1024 B 数据 `{item,len,status,data}`；读 `open + read({0x22,128,1})` 即可；
- 内核 `huawei_nv_read_item` 白名单 0..0x2B，经 SMEM 0x86 和 QMI 代理到 modem；
- 全 rootfs 扫描：NV 使用者只有 3 个固定 item（authconsole 0x22、webserver 0x2A、router 0/4-9/0x21）；
- 结论：协议本身不是障碍，障碍是 AP 侧代码执行。

### 6.4 aboot

- `s002` 流为 0x28 字节包装头 + 镜像本体；修正基址后字符串引用命中率 71/757 → 447/757；
- `fastboot` 命令表 12 项齐全，但全镜像无代码引用 `fastboot_init` → 不可达；
- `bootbk` 唯一入口是 `g_recovery == 0x5245434B`（RECK），全固件无人写该值；
- dload 无独立分支，`target_is_emmc_boot()` 是常量 0 的桩函数；
- 结论：bootloader 三条启动路线全部关闭。

### 6.5 升级器

- `cl_gz_uncompress_to_Flash` 无签名/哈希/版本校验，唯一门槛 `dev == 6`；
- 但 `osa_flash_*` 是文件后端，设备索引 0..5 映射到 `/online/*.bin` 与 `update_info.bin`，不碰分区；
- 本地升级版本校验 = 包内版本串最后一段 == `AT+CGMR` 最后一段，且受 `check_rule` 与 board 版本前缀两个旁路控制；
- 组件类型由上传文件名决定。

### 6.6 WebUI / app

- `authority.xml` 五张表；路径白名单 `FUN_000288B0` 前缀匹配 + realpath；
- `webserver` 无 `system/popen/exec*` 导入；17 个二进制 PIE + 栈保护 + FORTIFY；
- 静态文件 `..` 变体 404；路径类接口非 `/sdcard` 一律 `125003`；
- 表单 `csrf:` 前缀与 AJAX 请求头是准入关键。

### 6.7 结论

- 静态理解已完整：机制、协议、门控、写路径、WebUI ACL 均有对应代码证据；
- 静态层的瓶颈不是“看不懂”，而是“没有可触达的执行/写入落点”。

## 7. 方面 E：读取 NV 的路径

### 7.1 目标

读取 NV 0xC546 的 140 B（hash+salt），或 0xC547；这是暴破的前置条件。

### 7.2 `/dev/nv` 协议

- 协议已 100% 解出；但需要 AP 侧代码执行（root shell、注入或合法进程调用）；
- 已枚举全部 NV 使用者：authconsole、webserver、router；没有隐藏的“读 0x22”进程。

### 7.3 AT 面

- `^RSFR` 可读 SIMLOCK 与 LOGSAVE 日志，不含 hash；
- `^NVRDEX` 不存在；
- `^NVBACKUP`/`^NVRESTORE` 是 `0:OEMINFO` 自有备份的闭环，不能导出到 PC。

### 7.4 diag / QCDM

所有可达组合中 diag 沉默，无 NV 读通道。

### 7.5 P1：bbou NV 备份 → mass

- 静态链：agent/bbou 通过 `AT^NVBACKUP` 触发；分派器状态 90/100 + 事件 0x3c；
- 真机验证：官方同版本升级全流程 + USB 1 秒采样；只出现 1C20 [mass] 空 LUN（0 字节），未出现 [pcui,mass] 数据形态；
- 结论：NV 备份不进入 USB 暴露面，P1 证伪。

### 7.6 eUAP / authconsole

- authconsole 密码 = NV 0x22 验证 = SIM 解锁码（同一算法同一布局）；
- 登录后 `EUAP>` 即 `system()` root 执行，但 tty 为内部 UART `ttyHSL0`，PC 不可达；
- 形成“密码=解锁码”的循环依赖，无法作为入口。

### 7.7 结论

- 没有 PC 可达的 NV 读路径；
- 要读 0xC546，必须先取得 AP 代码执行（root）或走硬件（UART/EDL/NAND）；
- 这也是“只差一行代码执行”长期成为瓶颈的原因。

## 8. 方面 F：写入与执行路径

### 8.1 dload

- 帧式 `7E | payload | ~CRC16-X25 LE | 7E`；CRC 取反后小端；
- `^GODLOAD` 可进入 dload/HDLC 实验段，但 “installing” 会卡住，需断电恢复；
- 1200+ 帧盲探全部 NAK → 硬会话门；官方升级流程不走 dload，而走 HTTP 上传；
- 结论：协议全解，但无法建立有效会话。

### 8.2 升级包注入

- 官方 five 容器 17 组件全解；校验体系为 MD5-only（RSA 仅用于日志上报）；
- 注入 `nvdump`（304 B，open/read `/dev/nv`）到 `/system` cpio 的方案可构造；
- 但字节级实验证明：本地升级要求组件压缩流字节级等于原件 → 任何内容修改都会在应用阶段失败（状态 70）；
- 官方同版本包可稳定到 90（累计 5 次）；
- 结论：容器/校验全解，但本地升级通道不能携带修改。

### 8.3 nvram.bak 配置写

- 可下载 `/nvram.bak`，逐行 base64 解码；`Control=3` 重新生成；`/api/nvramul.cgi` 恢复；
- checksum = Σ `cl_CRC16`(行含 `\r\n`) mod 2^32；末行不参与；CRC16-CCITT poly 0x1021；
- 恢复管线三阶段；路径字段严格校验；只能写 22 个既定配置文件；
- 验证：`dialup_filterlist`、`toolsflag` 等写回成功；
- 结论：获得“22 文件内容受控写”能力，但不能任意文件写或路径穿越。

### 8.4 在线更新（FOTA）

- `update/config.xml` 服务器键可写；`sta_policy=2` 绕过网络门控；假服务器可令任意内容通过校验；
- CheckNewVersion → filelist（`dpath`、`md5` 大写、`size`、`spath`；组件需 `version`；validate MD5 短路需换内容）；
- 下载链路 30→40→60 打通；文件固定落盘 `/online/online_update.zip`；
- 安装 = 分区级刷写：webui 为 yaffs2 镜像，firmware1/2/iso 为裸 FW；webui 损坏=丢失控制通道；
- 结论：下载链可用，但不能作为任意写/执行通道；安装仅保留“官方镜像恢复/基线”用途。

### 8.5 文件上传与配置注入

- `filemanager/upload` 白名单 `.bin/.zip`；`cur_path` 不参与落点；`/sdcard` 读回 404；
- `/api/nvramul.cgi` 固定落点 `/nvram.bak`，`cur_path` 不参与；
- DMZ/IP/firewall/npdaemon：静态存在拼接点，但服务端校验或触发条件（PPP WAN）使其不可达；动态探针 `telnetd`/`;reboot` 未生效；
- 结论：没有“配置→root 执行”的可触达路径。

### 8.6 结论

- 已获得：22 文件配置写、FOTA 下载、`^DATALOCK` 预言机、直连 AT/WebUI；
- 仍缺：root 执行、NV 写、任意文件/分区写。

## 9. 方面 G：五层系统排查

### 9.1 bootloader

- fastboot：命令表/handler/`oem unlock` 齐全，但无 `fastboot_init` 调用；
- bootbk：需 SMEM `+0xB8 == "RECK"`，全固件无人写；
- dload：无独立分支，谓词恒 0；eMMC 路径是死代码。

### 9.2 内核

- `/dev/dload_nark` 可写 SMEM 六个字段，但节点 `0600 root`，且表里没有 RECK/UADB；
- `/dev/mtd*` 可读，但无安全写手段；改写 EFS2/modem 属无恢复高风险。

### 9.3 modem NV

- `^NVBACKUP`/`^NVRESTORE` 是 `0:OEMINFO` 自有备份的闭环；魔数 `0x3C4D5E6F`；版本校验；
- 外部无法注入；要利用必须先写 `0:OEMINFO`，而该分区不可写。

### 9.4 升级器

- `cl_gz_uncompress_to_Flash` 无签名/哈希；但 `osa_flash_*` 是文件后端，只写 `/online/*.bin`；
- 版本锁可伪造，但落点无价值。

### 9.5 WebUI / app

- 无 shell 导入；路径穿越全拒；固定 `/nvram.bak` 写；DMZ 返回 `100005`；免登录 POST 面仍受白名单；
- 17 个二进制均 PIE + 栈保护 + FORTIFY。

### 9.6 结论

- 五层全部关闭；错误模式一致：机能存在，但缺“把数据落到受保护区域”的入口；
- 该入口需要 root 执行环境、不受限 flash 写或硬件通道。

## 12. 结论与剩余方向

**机制**：100% 理解；锁码校验、NV 槽位、命令门控、写路径均有代码/实测证据。

**路线**：41 条路线系统性探索；R1–R4 闭环，R4b 受阻，更新包新构建复核无新入口。
R1=日志提取，R2=锁命令静态，R3=非 WAN 执行点，R4=官方镜像基线；R4b=dload 签名引擎。

**最终判断**：在“不拆机、不用官方渠道、只靠运行中的系统”下，没有找到可用解锁路径；软件层已结题。

**为什么 root 不是充分条件**：
- SIM 锁在 modem NV，AP root 只能读 `/dev/nv`，仍需 NV 写；
- `/dev/dload_nark` 无 RECK/UADB 字段，节点 `0600 root`；
- `^NVRESTORE` 只回灌 `0:OEMINFO` 自有备份；
- `/dev/mtd*` 改写 EFS2/modem 无恢复手段。

**剩余方向**：
1. R4b：签名实现不在现有镜像，需补分区（烧录/硬件）；
2. 网络守护进程 CVE（hostapd 2.1 / dnsmasq 2.51）——成本高、概率低；
3. 硬件 UART/EDL/NAND——需拆机，按约束排除；
4. 内存破坏——仅在出现具体候选时评估。

**项目价值**：机制知识、工具链、可复现的负结果、官方镜像基线。

## 附录 B：知识与协议清单

> 本附录集中列出本次逆向获得的可复用知识，按协议/子系统分组；函数地址与偏移对应本项目分析的固件版本。

### B.1 NV 三层链路与 item 映射

```text
AP 用户态 read(/dev/nv, item)
  → 内核 huawei_nv_read_item（白名单 0..0x2B）
  → SMEM 0x86 {item@+0xE0, magic@+0xE8}
  → huawei_notify_kernel_A2M(5)
  → modem qmi_huawei_server FUN_0205e50c
  → FUN_0205e3b0 → FUN_0205e37c（映射表）→ 读/写
```

- item 映射（16 项）：`0x22→0xC546`（50502/E0）、`0x2A→0xC4F2`、`0x2B→0xC542`、`0x00→0x1246`、`0x01→0xC3AB`、`0x04-09→0xC472-77`；
- SMEM 0x86 magic：读 `0x2014AA55`、写 `0x2014A5A5`、成功 `0x201455AA`；
- AP 侧 NV 使用者只有 3 个固定 item：authconsole（0x22）、webserver（0x2A）、router（0/4-9/0x21）。

### B.2 SIMLOCK 验证体系

- 码=8 位纯数字；`h2 = SHA256(SHA256(code) ‖ salt)`；`h2 == NV 0xC546[0:32]`；salt 位于记录 `0x40:0x60`；
- 成功：`*(GP+0x18fd)=0`；失败：全局计数 +1，上限 NV 50005=10；
- 槽位：`"OEM" → 0xC546`（50502/E0）、`"SIMLOCK" → 0xC547`（50503/E1）；记录长度 0x19B（411 B）；
- `^DATALOCK`：E0 提交口，参数 `{code,1,IMEI}`，本地 RAM 计数 3 次/启动，失败 `+CME ERROR:16`，不消耗 `^CARDLOCK`；
- `^SPWORD`：独立 3 次限制，全程未触碰。

### B.3 dload / HDLC

- 帧式：`7E | payload | ~crc16_x25 LE | 7E`；CRC 取反后小端；
- NAK 示例：`7e 03 00 06 9e4c 7e`；
- 1200+ 帧 ×5 头模型盲探全部 NAK → 硬会话门；官方升级流程不走 dload，而走 HTTP 上传；
- 组合脚本执行器只有 3 个：工厂 shell、开机 `start_usb`（固定 1F01）、`mbimd`（唯一自动者）。

### B.4 five 升级容器与内容锁

- 格式：`[前缀][主头 55AA5AA5][每流: 头 + comp_size + CRC16-X25 头校验 + chunk 表 + zlib 流 + pad]`；17 组件；
- 校验：运行时 MD5 回读；本地升级要求组件压缩流字节级等于原件（内容锁）；在线升级的期望 MD5 来自服务器，可伪造；
- 官方同版本 ZIP 本地升级累计 5 次到 90；内容修改在应用阶段返回 70。

### B.5 nvram.bak 配置面

- 逐行 base64（每行=内层行 + 终止符）；结尾 `<checksum>十进制</checksum>`；
- checksum = Σ `cl_CRC16`(原始行含 `\r\n`) mod 2^32；末行（checksum 行）不参与；
- `cl_CRC16`：CRC16-CCITT 表驱动 MSB-first，poly 0x1021，init 0，xorout 0；
- restore 管线 `0x736C` 三阶段（失败码 103016/103017/103018）；成功值 5，成功后重启；
- 路径字段严格校验：只能写 22 个既定文件，路径穿越被拒（103018）。

- `dload_init` → `nark_api_init`：`huawei_smem_alloc(0x86, 0xCD0)`，映射 `+0x2C/+0xA8/+0xB0/+0xD0/+0xDC/+0x508`；
- `misc_register`（`/dev/dload_nark`，minor 255）+ `/proc/dload_nark`；
- `visit_dload_smem` 选择子：0→`+0x2C="NFLD"`、3→`+0xA8="PUDS"`、6→`+0xD0="PSND"`、9/0xB→`+0xB0="RNDS"/"RNNO"`、0xF→`+0xDC="DLCF"`；
- 边界：节点默认 `0600 root:root`；`/proc` 只读；表里没有 `+0xB8`/`+0xC8`。

### B.10 升级器写路径与版本锁

- `cl_gz_uncompress_to_Flash(fd, dev, out)`：gunzip 流直写，无签名/哈希/版本校验，唯一门槛 `dev == 6`；
- 但 `osa_flash_*` 是文件后端：索引 0..5 → `/online/firmware1.bin`、`firmware2.bin`、`iso.bin`、`web_ui.bin`、`/data/userdata/update_info.bin`、`/online/update_state.bin`；
- 本地升级版本校验：包内版本串最后一段 == `AT+CGMR` 最后一段；受 `check_rule` 与 board 版本前缀两个旁路控制；
- 组件类型由上传文件名决定（`HILINK` + 是否含 `_`）。

### B.11 WebUI 访问控制模型

- `authority.xml` 五张表：`limited_res_type_list`、`limited_fs_res_type_list`、`not_need_login_visited_res_list`、`need_login_get_restful_list`、`not_need_login_post_restful_list`；
- 路径白名单 `FUN_000288B0(path, mode)` = 前缀匹配；`mode==2` 时先做 `realpath`；
- 表单 `csrf_token` 字段值必须带 `csrf:` 前缀；AJAX 用请求头 `__RequestVerificationToken`；
- 结果码：125003=无权限/路径被拒；100001=参数或内容错误；100005=参数校验失败（IP）；100002=SD/文件不可用。
