# HWD31 非软件路径分析（doc/03）

> 生成：2026-10-21 晚。范围：除“在运行中的系统里找软件入口”之外，还有哪些分析与解锁可能。
> 约束前提：用户明确不拆机、不做硬件改造，也不使用官方渠道；本文只做评估与记录，不执行任何硬件操作。
> 证据等级沿用全套文档：A=逐条实证；B=静态/文档可证；C=推断或外部经验。

---

## 1. 一句话结论

在“不拆机 + 不用官方渠道”两个约束同时成立时，非软件路径全部不可达。若放宽任一约束，按性价比排序：

1. 官方/运营商解锁（最省事、最合法，但需要契约资格与费用）；
2. 第三方解锁服务（花钱买码，风险是诈骗与二次锁）；
3. NAND 离线读取 → 拿到 hash+salt → 离线暴破（要拆焊芯片，但只用本项目已掌握的知识）；
4. UART/JTAG 调试口（要焊接，回报是 root shell，仍需再解决 NV 写）；
5. USB EDL(9008)（要短接触点 + firehose programmer，本机包内没有）。

## 2. 先把“解锁”缺什么钉死

- 锁记录：modem NV 0xC546（50502 / E0）与 0xC547（50503 / E1），每条 0x19B（411 字节）；
- 校验：h2 = SHA256( SHA256(code8) ‖ salt )，h2 == 记录[0:32]，salt = 记录[0x40:0x60]；
- 上限：NV 50005 = 10 次；本机 ^CARDLOCK: 1,10,0，0/10 已用；
- 因此只有两条达成路径：
  - A. 拿到 8 位码 → 单次 AT^CARDLOCK 提交；
  - B. 改写 NV（清锁状态，或直接写已知码的 hash+salt）→ 重启生效。

下文每个通道都在回答同一件事：能否拿到码，或能否获得“写 NV 的物理能力”。

## 4. 逐通道说明

### C1 官方解锁（au / 售后）

- 原理：运营商侧持有 IMEI→解锁码的数据库，或可远程下发解锁；
- 本项目已确认：码不是 IMEI 的函数（全镜像无 MD5 IV/K 表、历史公式候选全失败），所以只能“问运营商要”；
- 需要：合约期满/无欠费/符合解锁政策；费用通常为手续费；
- 评价：唯一“确定能成”的路径，但被“不用官方渠道”约束排除。

### C2 第三方解锁服务

- 原理：商家用内部接口/数据库换码，或提供“远程刷写”；
- 现实风险：IMEI 泄露、收钱不出码、“解锁”后二次锁；法律定性因地区而异；
- 评价：若将来放宽，优先要求“先出码后付款 + 支持 ^DATALOCK 免计次验证”（本机已具备 3 次/启动的预言机，可先验码再提交 ^CARDLOCK）。

### C3 UART 调试口（ttyHSL0）

- 已知：boot img cmdline 为 console=ttyHSL0,115200,n8；本机 authconsole 就挂在该串口（密码 = SIM 解锁码，循环依赖，已证伪）；
- 但 UART 的 bootloader 命令行/内核控制台本身可能提供 root shell 或启动参数控制（androidboot.*、init=/bin/sh 之类），取决于测试点是否引出；
- 需要：拆机、找到 TX/RX/GND 测试点并焊接（多数机型有 3~4 个焊盘）；
- 收益：root shell → /dev/nv 读 0xC546（140B）→ 回到“离线暴破”；不是直接解锁；
- 评价：投入大、回报是“再走一遍已知路”；本项目已证明“拿到 root 也缺 NV 写通道”，但读 NV 恰好只需要 root，所以 UART 是“读 hash”的最短硬件路径。

### C4 JTAG

- 需要：识别 AP/modem 的 JTAG 引脚（通常未引出）、专用调试器；
- 收益：可 halt CPU、直接读写内存/外设，理论上可绕过一切软件限制；
- 风险：操作不当会锁死 SoC；成本极高；
- 评价：不建议，除非有同型号的成功案例与图纸。

### C5 USB EDL（9008）

- 已知：sbl1_sahara.c 表明 9008 在引导层具备；但本机包内没有 firehose programmer，且进入 9008 需要短接/测试点或特殊 USB 命令；
- 收益：EDL 可读写全部分区（含 modem NV 与 EFS），是“最彻底”的硬件路径；
- 风险：极高（错刷 = 变砖，且无恢复手段）；
- 评价：仅在拿到对应平台（MDM9635）的 programmer 且愿意承担变砖风险时才考虑。

### C6 NAND 芯片离线读取（chip-off / ISP）

- 原理：拆下 NAND（或在线 ISP 夹取），用编程器读全盘镜像，离线解析 EFS/NV，直接得到 0xC546 的 411 字节记录（hash+salt）；
- 之后：离线暴破 8 位纯数字（本项目已验证 brute.exe 约 5.84M hash/s，单轮约 17 秒），得到码 → 单次提交；
- 需要：BGA 返修台/植球、NAND 编程器、对 yaffs2/华为 EFS 布局的解析（本项目已有大量积累）；
- 风险：拆焊损坏、数据不可读；成本高；
- 评价：这是“完全离线、不依赖设备运行”的最可行路径，也是唯一“用现有知识就能闭环”的硬件路线（读→暴破→提交）。

### C7 fastboot / bootbk / dload（已证伪）

- fastboot：命令表 12 项、oem unlock 字符串都在，但全镜像无任何代码引用 fastboot_init → 不可达；
- bootbk：唯一入口 g_recovery == 0x5245434B（RECK），全固件无人写该值；
- dload：aboot_init 分支谓词恒 0，dload 标志只影响 DTB 读取；
- 评价：这条路已经关死，不要重复投入。

### C8 同型号 NV 备份复用

- 若拿到另一台同型号、已解锁设备的 NV 备份：其中的 salt 是随机的，hash 对应的是那台机的码；
- 直接写到本机不会解锁（码不同），且写 NV 仍需物理通道；
- 唯一价值：验证记录布局/解析器，或作为“写 NV 的对照样本”。

### C9 产线/维修工具

- 华为/高通产线工具（如 NV writer、factory download tool）能直接写 NV，但属内部工具，公开渠道基本拿不到；
- 若将来出现泄露版本，需先确认：支持 MDM9635、支持 0x19B 记录格式、能离线校验；
- 评价：可作为“补分区/写 NV”的现实替代，但不可预期。

### C10 SIM / 漫游侧

- 换 au 卡、国际漫游、白名单 APN 等，都只影响“能不能上网”，不改变网络锁状态；
- 本项目已确认：无 SIM 时 ^DATALOCK 仍可验码（免计次），说明锁与 SIM 身份无关；
- 评价：与解锁无关，排除。

## 5. 决策对比（若将来放宽约束）

| 目标 | 最短路径 | 前提 | 代价 | 成功率 |
|---|---|---|---|---|
| 只想要“能用” | C1 官方解锁 | 合约资格 | 手续费 | 高（政策内） |
| 不想拆机、愿花钱 | C2 第三方 | IMEI + 付款 | 数十~数百元 | 中（有诈骗风险） |
| 愿意拆机、要“自己搞” | C6 NAND 离线读 | 编程器/返修台 | 高 | 中高（读成功即可闭环） |
| 愿意焊接、想拿 shell | C3 UART | 测试点/焊接 | 中高 | 中（取决于测试点） |
| 追求“彻底控制” | C5 EDL | programmer + 短接 | 极高 | 低（变砖风险） |

## 6. 若约束放宽的推荐顺序

1. 先试 C1（官方）：唯一“确定性高、无副作用”的路径；
2. 再评估 C2（第三方）：只接受“先验码后付款”，用 ^DATALOCK 3 次/启动先验证，再决定是否提交；
3. 要自己动手 → C6：离线读 NAND → 取 0xC546 记录 → 暴破 → 单次提交；这是本项目知识体系能直接复用的路线；
4. C3 UART 作为“拿 root 但未必能写 NV”的补充；
5. C5 EDL / C4 JTAG 仅在拿到对应工具且有变砖承受能力时考虑。

## 7. 明确不建议

- 不拆机就能用 USB 直接进 EDL/fastboot：本机已证伪（无调用、无短接条件）；
- 买“解锁软件/盒子”：多为诈骗或只能解旧机型；
- 对 NAND 直接热风枪吹焊：无返修台时损坏率极高；
- 任何“先付款后给码”的第三方：无法验证时不要提交 ^CARDLOCK（只有 10 次）。

## 8. 结论

- 软件层：R1–R4 已闭环、R4b 受阻于未 dump 分区，没有可用解锁路径；
- 非软件层：全部依赖物理接触（拆机/焊接/读芯片）或官方/第三方渠道；在“不拆机 + 不用官方渠道”下同样不可行；
- 唯一“用现有知识就能闭环”的硬件路线是 C6（NAND 离线读 → 暴破 → 单次提交），但它需要拆焊，与当前约束冲突；
- 因此本项目的最终结论保持不变：在当前约束下，SIM 锁不可解除；若将来放宽，按 §6 的顺序执行。
